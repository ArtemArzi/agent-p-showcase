# Пользовательские сценарии

| Пользовательская задача | Реализованный путь в основной кодовой базе | Граница подтверждения |
| --- | --- | --- |
| Узнать цену и услугу | Info обращается к каталогу CRM | Консультация не создаёт запись |
| Выбрать услугу, мастера и время | Canvas уточняет параметры и формирует карточку | Перед созданием проверяется актуальность |
| Подтвердить запись | Executor запрашивает недостающий контакт и вызывает CRM | Успех зависит от ответа CRM |
| Посмотреть или отменить | Manager работает с записями клиента | Текущий production-путь не проверялся |
| Перенести на другое время | Rescheduler меняет параметры записи | Реальная внешняя мутация здесь не выполнялась |
| Нет подходящего времени | Другой мастер/день и расширение горизонта поиска | Наличие логики и тестов не доказывает live E2E |
| Повторилось подтверждение | Отпечаток команды и проверки повтора | Гарантии внешней CRM устанавливаются отдельно |
| Разошлось состояние | Восстановление выбора | Противоречие не маскируется успехом |

## Проверяемые контракты публичного примера

1. Без подтверждения CRM не вызывается.
2. При доступном времени и согласованных параметрах тестовая CRM вызывается один раз.
3. Занятое или неизвестное время не приводит к созданию.
4. Конфликт и неполные параметры блокируют создание.
5. Повтор возвращает ранее полученный результат.
6. Другое время считается другой командой.
7. Перестановка списка услуг не меняет идентичность команды.
8. Неясный ответ тестовой CRM сохраняется для сверки, повтор не вызывает ещё одну запись.
9. Отказ тестовой CRM не называется успехом.

Все ID и дата в примере вымышленные. Нет реальных телефонов, адресов, сообщений клиентов или выгрузок.
